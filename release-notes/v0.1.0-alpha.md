# v0.1.0-alpha — release notes

> **Status:** alpha. Public, but not yet a SemVer-stable contract.
> Expect minor releases to carry occasional breaking changes until
> v0.2.

This is the **first public release** of CogniDQ. This document is a
companion to [CHANGELOG.md](../CHANGELOG.md); it is more narrative and
less exhaustive.

---

## What CogniDQ is

CogniDQ is an open-source data quality control plane:

- multi-tenant, with a three-level hierarchy of platform, tenant,
  workspace,
- rules-first: a versioned, schedulable check that produces a numeric
  score and a sample of failing rows,
- batteries-included for the demo: a `docker compose up` and a
  `make seed` give you a full working stack with synthetic data,
- explicitly scoped: see [docs/product-scope.md](../docs/product-scope.md)
  for the non-goals.

It is built around four concepts: **datasets**, **rules**,
**executions**, **issues / incidents**. Everything else is plumbing.

## Highlights

- Apache-2.0 licensed.
- Eight stable rule types (completeness, uniqueness, validity, regex,
  accepted_values, range, comparison, consistency) and two experimental
  ones (freshness, custom_sql) — see
  [docs/rule-types.md](../docs/rule-types.md).
- Two execution backends: **SQL pushdown** for small datasets and
  **Apache Spark** for large ones, chosen automatically per rule.
- Built-in RBAC with seven roles — see [docs/rbac.md](../docs/rbac.md).
- Failed-row evidence with sensitivity-aware masking — see
  [docs/evidence.md](../docs/evidence.md).
- Auto-issue creation; manual incident grouping with a timeline —
  [docs/issues.md](../docs/issues.md), [docs/incidents.md](../docs/incidents.md).
- A REST API documented by OpenAPI 3.1 at `/api/v1/openapi.json`.
- A Makefile-driven dev experience: `make help`, `make start`,
  `make migrate seed test lint`.
- CI: ruff + ruff-format, eslint, vitest, pytest, gitleaks.
- A pre-commit config you can opt into with `pre-commit install`.

## What is intentionally *not* in this release

These are documented as out-of-scope or held back to the commercial
edition; see [docs/open-source-strategy.md](../docs/open-source-strategy.md):

- SAML / OIDC / SCIM. Local users + JWT + personal API tokens only.
- Real-time streaming.
- Source-system writebacks. Connectors are read-only by design.
- A bundled metadata catalog. We integrate; we don't replace.
- Hosted SaaS. The OSS repo is everything you need to self-host.

## Known limitations

The honest list lives in
[docs/known-limitations.md](../docs/known-limitations.md). Highlights:

- Only PostgreSQL is exercised in CI. Other connectors are beta or
  experimental.
- The flow / DAG builder is gated by `ENABLE_COMPLEX_FLOW_BUILDER` and
  off by default.
- Dashboards recompute aggregates on each request; pre-aggregation
  lands in v0.2.
- No Helm chart yet.
- No published Docker images yet — build locally.
- No release-binary signing yet.

## Security notes

- The default compose configuration is **not** safe for production
  exposure. Read [docs/production-hardening.md](../docs/production-hardening.md)
  before exposing CogniDQ off your laptop.
- Demo passwords are intentionally weak so the first-time install is
  painless. Replace them.
- Encryption keys must be generated locally; the example file ships
  with placeholders that the app refuses to start with.
- Pre-1.0 releases have not been independently security-audited.
- Vulnerability reporting: [SECURITY.md](../SECURITY.md). Use
  [GitHub Security Advisories](https://github.com/cogniDQ/cognidq-public/security/advisories/new)
  privately; do not open public issues for vulnerabilities.

## Upgrade notes

This is the first release. There is nothing to upgrade from.

For future releases the supported upgrade path will be: read the
CHANGELOG, take a Postgres backup, deploy new images, run
`alembic upgrade head`. We will document any deviations explicitly.

## How to get started

```bash
git clone https://github.com/cogniDQ/cognidq-public.git
cd cognidq-public
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env
# generate two Fernet keys; set MINIO_ROOT_PASSWORD; see getting-started.md
docker compose up -d
make migrate seed
```

Open <http://localhost:5173>, sign in as
`steward@example.com` / `change-me-strong-password`, follow
[docs/first-check.md](../docs/first-check.md).
